| 编号 | 修复后的行为 | 回归 |
|---|---|---|

| C2 | 服务器及规则 ID 限制为 1–128 字节，限制应用于配置和变更校验。日志继续按 JSON 转义后的大小缩短正文。防御性事件分页遇到无法容纳的首条记录时保留游标并要求 resync，不再静默跨过。 | 最大控制字符 ID、多字节名称和大量转义正文仍可写入/读回单条有界日志；129 字节配置 ID 拒绝；超页事件不前移游标。 |
| C3 | 增加 `status_view`：持有同一应用状态锁返回 config 与 snapshot，服务端完成一次性查询筛选，客户端再核对 revision 一致性。 | 服务端快照版本测试；私有 IPC 返回混合版本时真实 CLI 返回 revision_conflict；原 watch 重连测试更新为新协议后保持覆盖。 |
| C4 | 生产事件携带 EventContext 与产生时间；journal 保留它们，只分配消费序号。历史归属不再套用消费时的新配置。缺少原始 context 的旧记录保留已有标签或稳定 ID，不再从当前配置或后续事件猜测归属。 | 生产者测试覆盖排队后改名、同代元数据调整、同 ID 改服务器后的旧代迟到事件；journal 测试检查持久与实时事件的原时间、名称、服务器、组。 |
| C5 | watch 在第一份可读配置上解析选择器，即使 IPC 已失联。已保存规则以 unverified 显示，缺失名称/组/服务器仍立即报错。 | `tests/postfix_queries.py`：真实 CLI + 私有 IPC，合法名称/ID/组/服务器/全部共 5 种选择保留规则；3 种缺失选择拒绝。 |
| C6 | 状态响应按实际 JSON 序列化大小设预算，超限时明确截断诊断摘要；一次性单规则查询在服务端先筛选，可返回该规则完整错误。联合快照具有能力协商，旧后台返回升级指引。 | 512 规则 × 多字节/转义长错误，最大合法配置和运行快照组合均在 1 MiB 帧内；真实私有后台接收 512 条规则后，全量与单条 CLI 查询均成功，单规则保持超过 7,000 字符的完整错误；旧/新后台能力测试。 |
| DH01 | 已删除对象的精确历史 ID 优先于其它历史对象的同名别名；规则和服务器 follow 固定该身份。 | 两个均已删除的对象名称/ID 跨时间碰撞，静态和 follow 均只选原 ID；历史标签轮转后仍不跳到另一对象。 |

## 范围与限制

三平台服务事务使用假管理器，另以本机私有后台验证启动、停止、重启与长路径 IPC；不注册用户的真实系统服务。存储故障用私有 I/O 注入，未进行真实断电或磁盘耗尽。异常任务的关闭/恢复使用受控注入，不能据此推断真实网络一定会进入该状态。编辑器并发保存的具体支持边界见存储记录。原报告列出的未确认候选不计作本次新增缺陷，也未承诺项目不存在其它问题。
